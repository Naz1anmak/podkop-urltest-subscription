# Podkop Auto Config Script
Это вспомогательный инструмент для OpenWrt, который добавляет недостающую функциональность работы с подписками в плагин Podkop (sing-box).

По умолчанию Podkop не имеет встроенной системы для автоматической загрузки и обновления ключей из внешних ссылок-подписок. Данный скрипт устраняет это ограничение, превращая статическую конфигурацию в динамическую систему с автоматическим перебором серверов.

## 🚀 Возможности
- 📥 Поддержка RAW ссылок (GitHub и др.)
- 🌐 Парсинг HTML/текстовых страниц с ключами
- 🔗 Поддержка прямых ссылок (vless://, ss://, trojan:// и др.)
- ⭐ Приоритизация прямых ключей (всегда попадают в конфиг)
- 📶 Пинг через временный sing-box: в Podkop попадают `LIMIT` самых быстрых живых серверов из всех подписок
- 🧪 Проверка каждого ключа кодом самого Podkop и установленным `sing-box check`: битые ключи отсеиваются до записи в конфиг
- ✂️ Быстрый поиск битых ключей делением пополам (чистый набор — одна проверка)
- 🧹 Очистка ссылок от мусора без изменения их параметров
- ↩️ Откат на прежний конфиг, если после обновления sing-box не запустился
- ⚡ **Автоматическая интеграция с Podkop (URLTest, Cron)**

## ⚙️ Инструкция по установке

### ✦ Шаг 1: Установка
Подключитесь по **SSH** к роутеру и выполните команду:
```bash
wget -O /usr/bin/podkop-update https://raw.githubusercontent.com/Naz1anmak/podkop-urltest-subscription/main/update.sh && \
chmod +x /usr/bin/podkop-update
```

### ✦ Шаг 2: Настройка источников
Откройте файл в **vi** или **nano** и впишите свои ссылки в переменные `SOURCE_1`, `SOURCE_2`, `SOURCE_3`:

```bash
vi /usr/bin/podkop-update
```
(нажмите i для редактирования, Esc затем :wq для сохранения и выхода).

Или установи более удобный редактор (apk add nano)
```bash
nano /usr/bin/podkop-update
```
Сохраните изменения и выйдите из редактора.

### Проверка вручную
После настройки запустите скрипт вручную:
```bash
/usr/bin/podkop-update
```
Если всё прошло без ошибок, Podkop будет обновлён. В логе видно, какие ключи отброшены и почему, например:
```
⛔ Отброшен: 🇳🇱_Amsterdam — unknown uTLS fingerprint: unsafe
⛔ Отброшен: 🇩🇪_Frankfurt — The xhttp transport is not supported by the installed sing-box (podkop-engine r11 or later is required). Aborted.
```

### ✦ Шаг 3: Автообновление (Cron)
Если ручной запуск прошёл успешно, добавьте обновление например на 6 утра каждый день вместе с логом:
```
(grep -q "/usr/bin/podkop-update" /etc/crontabs/root || echo "0 6 * * * /usr/bin/podkop-update > /var/log/podkop-update.log 2>&1" >> /etc/crontabs/root) && /etc/init.d/cron restart
```

Лог последнего запуска будет в `/var/log/podkop-update.log` (каждый запуск перезаписывает его, файл лежит в оперативной памяти роутера).

## 🧹  Скрипт удаления
Удалить скрипт и задание cron можно одной командой:
```sh
rm -f /usr/bin/podkop-update && \
sed -i '/podkop-update/d' /etc/crontabs/root && \
/etc/init.d/cron restart
```

## 🧠 Как это работает
- Загружает источники (текст, HTML или base64-подписку)
- Извлекает ключи: vless, ss, trojan, hysteria2/hy2, socks4/socks5 (`socks://` переводится в `socks5://`)
- Чистит мусор (HTML-экранирование, пробелы, обрезанные ссылки), параметры ключей не трогает. Правки только две: reality-ключу без `fp` подставляется `fp=firefox` (настройка `DEFAULT_FP`), а vless/trojan без `type` получает явный `type=tcp`
- Ставит прямые ключи первыми, остальные перемешивает
- Каждый кандидат собирается в outbound функцией Podkop `sing_box_cf_add_proxy_outbound` из `/usr/lib/podkop` — тем же кодом, которым Podkop соберёт конфиг при запуске
- Пачка outbound'ов проверяется одним `sing-box check`; если не прошла — делится пополам, пока не найдутся конкретные битые ключи
- Проверенные пингуются: поднимается временный sing-box с Clash API на `127.0.0.1` (это HTTP-интерфейс sing-box, через него он сам меряет задержку любого сервера) и параллельно проверяет каждый сервер через `TEST_URL` (по умолчанию `https://www.gstatic.com/generate_204`). Мёртвые и медленнее `MAX_DELAY` (по умолчанию 2000 мс) отбрасываются, живые берутся по возрастанию задержки. Podkop при этом не трогается
- Кандидаты идут порциями по 100: проверка → пинг → следующая порция. Пингуются все ключи подписок, поэтому в выборку попадают самые быстрые из всех, а не первые попавшиеся. Живых в бесплатных подписках обычно 2–15%. На роутере это около 20–30 секунд на каждые 100 ключей
- Прямые ключи остаются, даже если не ответили. Если из подписок не ответил никто (например, пропал интернет), конфиг не меняется. Если временный sing-box не запустился — ключи берутся без учёта пинга. Выключить пинг: `PING_CHECK=0`
- Проверяет итоговый набор целиком
- Если список не изменился — Podkop не перезапускается
- Сохраняет копию `/etc/config/podkop`, записывает ключи, перезапускает Podkop и ждёт запуска sing-box. Не запустился — возвращает прежний конфиг

Проверка идёт установленным на роутере sing-box, поэтому учитывает его версию: например, xhttp-ключи пройдут на podkop-engine и будут отброшены на ванильном sing-box.

Если библиотек Podkop или sing-box нет (очень старая версия Podkop), скрипт предупредит и запишет ключи без проверки — защитой останется откат.

## ⚠️ Требования
- Доступ к интернету
- Podkop установлен
- Podkop 0.7.14 или новее (проверено на 0.7.14–0.7.24)

## 📌 Примечания
- Пинг отбирает живые серверы на момент запуска, а дальше между ними переключается сам Podkop (URLTest)
- Подписка может дать меньше `LIMIT` серверов, если живых в ней мало — это нормально
- Если ключей нет или после проверки не осталось рабочих вариантов, текущий конфиг не меняется
- Код выхода: `0` — обновлено или менять нечего, `1` — обновление не применилось (был откат, ни один сервер не ответил или итоговый набор не прошёл проверку)
